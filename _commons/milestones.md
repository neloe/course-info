This course may commit milestones on programming projects and assignments.
A commit consists of making a set of related changes to your assignment code, writing a *commit message*, and performing the Commit operation ("Commit to Master" in GitHub Desktop).

Some assignments in this course will specify *commit milestones* in the assignment writeup.
For each milestone you are expected to have at least one unique commit that satisfies the milestone.
The message does not necessarily need to explicitly specify which milestone it satisfies (with the "Milestone x" message), but should contain enough detail to make it clear that the commit corresponds to a specific milestone.

# Example

Many programming assignments will have the following mielstone:

1. Add the required source header to `list of source files`

To complete this milestone, you must add the required source header (specified on the course website) to the specified source files, associate a commit message with the changes, and make the commit.
While "Milestone 1" would be an acceptable commit message, you should get in the habit of writing more descriptive messages.
Better commit messages might be:

* Add comment header to source files
* Write academic integrity comment header

As you write commit messages, try to briefly summarize the changes you made.
If you need to have a longer message, add a message body (think of the commit message as an email with a subject and a body if you need more detail).

# Multiple Commits per Milestone

It is difficult to commit too often.  
In general, if you are going to stop working on a project, you should make a commit and push your work.
These commits can be used to leave yourself messages on where you were in your thought process while working on your assignment.
Don't be affraid to commit early and commit often!

It is always acceptable to have more than one commit per milestone.
